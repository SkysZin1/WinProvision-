# 0.7.1 release notes

This patch fixes two readiness checks that could incorrectly block app installation:

- If Microsoft's connectivity endpoint fails, the picker checks the WinGet download service using an HTTPS HEAD request, without downloading the source package. Both checks have bounded timeouts and diagnostic logs.
- The WinGet version probe retains its process handle so Windows PowerShell 5.1 can read the exit code reliably.

Validation includes automated Builder/XML checks, bilingual WPF checks, 15 worker scenarios per language and successful application installation after retrying with these fixes on an existing Windows installation.
